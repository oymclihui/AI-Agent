## 1. 快速上手

### 1.1 启动服务

**Windows（推荐）**

```powershell
# 项目根目录
.\start.ps1          # 同时启动前后端
# 或分别启动
.\start_backend.ps1
.\start_frontend.ps1
```

**手动启动**

```bash
# 后端（端口 8000）
cd backend
.venv\Scripts\activate    # Windows
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 前端（端口 3000）
cd frontend
npm run dev
```

浏览器访问：**http://localhost:3000**

- API 文档：http://localhost:8000/docs
- 健康检查：http://localhost:8000/health

### 1.2 首次登录

1. 打开 http://localhost:3000 ，自动跳转至 **登录页** `/login`
2. 使用默认管理员账号（首次启动自动创建）：
   - **工号：** `admin`
   - **密码：** `admin123`
3. 登录成功后进入首页；侧边栏可进入各功能模块

> **安全提示：** 生产环境请在 `backend/.env` 中修改 `DEFAULT_ADMIN_PASSWORD` 和 `SECRET_KEY`，并尽快修改管理员密码。

## 2. 登录与账号

### 2.1 登录方式

- 支持 **工号** 或 **邮箱** + 密码登录
- 登录状态保存在浏览器本地（JWT Token），默认有效期 **7 天**（由 `ACCESS_TOKEN_EXPIRE_MINUTES` 控制）
- 未登录时访问业务页面会自动跳转到 `/login`

### 2.2 注册新用户（可选）

若后端开放注册接口，可通过 API 注册：

```http
POST /api/v1/auth/register
Content-Type: application/json

{
  "employee_no": "10001",
  "email": "user@company.com",
  "password": "your-password",
  "display_name": "张三"
}
```

注册成功后返回 Token，与登录相同。

### 2.3 退出登录

进入 **设置** 页（侧边栏 **Settings / 设置**）→ 点击 **退出登录**。

## 3. 个人设置与 API Key

路径：**设置** → http://localhost:3000/settings

### 3.1 为什么需要个人 Key？

平台支持两种 LLM 密钥来源：

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 高 | **个人模型 Key**（设置页配置） | 仅当前用户使用，互不影响 |
| 低 | 全局 `.env`（如 `OPENAI_API_KEY`） | 所有用户共用，适合 Ollama 或统一网关 |

### 3.2 配置步骤

1. 打开 **设置** 页
2. 在「个人模型 Key」区域填写：
   - **Provider**：如 `openai`、`anthropic`
   - **Model ID**（可选）：限定该 Key 仅用于某模型
   - **API Key**：密钥本身
   - **Base URL**（可选）：OpenAI 兼容接口地址，用于内部网关
3. 点击 **保存**
4. 已保存的 Key 会显示脱敏预览（如 `sk-****abcd`），可单独删除

### 3.3 对接内部 OpenAI 兼容服务

示例（内部推理网关）：

| 字段 | 示例值 |
|------|--------|
| Provider | `openai` |
| Base URL | `https://your-internal-gateway/v1` |
| API Key | 网关分配的 Key |
| Model ID | 留空或填具体模型名 |

之后在 **Model Hub** 中创建 provider 为 `openai` 的模型配置，并填写相同 Base URL。

## 4. Model Hub（模型中心）

路径：**Model Hub** → http://localhost:3000/models

### 4.1 功能概览

- **查看** 已配置的 LLM 列表
- **新建** 模型配置（名称、Provider、模型 ID、Base URL 等）
- **编辑** 已有配置
- **设为默认**：对话与 Agent 未指定模型时使用
- **删除** 不再使用的配置
- **推理参数**：temperature、top_p、max_tokens、stop 等

### 4.2 新建模型配置

1. 点击 **新建** / **Add**
2. 填写基本信息：
   - **名称**：显示用，如「GPT-4o 生产」
   - **Provider**：`openai` / `anthropic` / `ollama` / `azure` 等
   - **Model ID**：如 `gpt-4o`、`qwen3.6:35b`
   - **Base URL**（OpenAI 兼容或 Ollama 时）：如 `http://localhost:11434`
3. 展开 **推理参数**（可选）：
   - `temperature`：0–2，越高越随机
   - `top_p`：核采样
   - `max_tokens`：最大输出长度
   - 其他参数见表单说明
4. 保存

### 4.3 设为默认模型

在模型列表中点击 **设为默认**；系统全局默认对话将使用该配置（用户未在 Chat 中单独选模型时）。

### 4.4 Ollama 本地模型

| 字段 | 值 |
|------|-----|
| Provider | `ollama` |
| Model ID | 本机已 pull 的模型名，如 `qwen3.6:35b` |
| Base URL | `http://localhost:11434`（或 `.env` 中 `OLLAMA_BASE_URL`） |

确保本机 Ollama 已启动且模型已下载：

```bash
ollama pull qwen3.6:35b
ollama pull nomic-embed-text   # 知识库嵌入
```

## 5. 对话（Chat）

路径：**Chat** → http://localhost:3000/chat

### 5.1 基本对话

1. 左侧 **新建对话** 或选择历史会话
2. （可选）选择绑定的 **Agent**，自动注入其技能与工具
3. （可选）选择 **模型**
4. 输入消息，Enter 发送；支持 **流式输出**

### 5.2 附件与推荐问题

1. 点击输入框旁的 **附件** 按钮，上传文档（如 PDF、Word、TXT 等）
2. 上传成功后，系统会用 LLM 分析附件内容，生成 **3 条推荐问题**
3. **点击推荐问题** → 自动填入输入框，可编辑后发送
4. 也可忽略推荐，自行输入问题

> 推荐问题基于当前附件生成；更换附件会重新分析。

### 5.3 绑定智能体与工具确认

1. 在 Chat 顶部选择 **Agent**（如「桌面操作员」）
2. 该 Agent 若配置了 `desktop_*`、`http_request` 等工具，对话将走 **Agent 执行器** 而非纯 LLM
3. 输入区上方可能出现两类确认横幅：
   - **待确认的桌面回放**（琥珀色）：Sidecar 回放需批准
   - **待确认的工具调用**（紫色）：`http_request`、`fetch_mail` 等 L2 工具需批准
4. 点击 **批准执行** 后 Sidecar / 工具才会真正运行

### 5.4 智能沉淀（Deposit）

长对话结束后，系统可能自动分析是否值得沉淀为技能、知识库、智能体或数字员工，并在输入区上方展示 **智能沉淀建议**。勾选类型后点 **确认沉淀** 即可一键创建。

### 5.5 语音输入

输入框旁 **麦克风** 按钮：浏览器录音 → 后端转写（`POST /chat/transcribe`）→ 文本填入输入框。

### 5.6 删除会话

| 操作 | 方法 |
|------|------|
| 删除单条 | 会话列表项右侧 **垃圾桶** 图标 |
| 清空全部 | 会话列表顶部 **清空全部** 按钮 |

删除后不可恢复，请确认后再操作。

### 5.7 会话自动过期

- 超过 **30 天** 未更新的会话会被系统自动清理
- 可在 `backend/.env` 调整：`CONVERSATION_RETENTION_DAYS=30`
- 打开会话列表时也会触发过期清理

## 6. 会话沉淀：存为技能 / 知识库

在 **当前对话** 打开时，工具栏提供：

### 6.1 存为技能

1. 点击 **存为技能**
2. 系统将对话记录交给 LLM，提炼为 **SOP 格式 Markdown**（适用场景、操作步骤、输出格式、注意事项）
3. 生成后可在 **Skills** 页查看、编辑，并绑定到 Agent

适用：重复性工作流程、操作规范、方法论沉淀。

### 6.2 存入知识库

1. 点击 **存入知识库**
2. 系统将对话整理为 Markdown 文档，写入您的知识库并完成向量索引
3. 之后在 **Knowledge** 页可检索该内容

适用：会议纪要、调研结论、FAQ 等事实性内容。

## 7. 数据隔离与共享模板

登录后，您创建或导入的资源会标记 **所有者（owner_id）**：

| 模块 | 隔离规则 |
|------|----------|
| 智能体 Agents | 仅见/改自己的；平台种子模板全员可见 |
| 技能 Skills | 同上 |
| 工作流 Workflows | 同上 |
| 知识库 Knowledge | 同上 |
| 对话 Chat | 仅自己的会话 |
| 数字员工 Employees | **按组织 RBAC**：默认仅自己的；部门负责人/接口人见子树；高管见全公司 |
| 运营大屏 `/screen` | 需 `dashboard:view`（高管/部门负责人等）；普通 `operator` **无入口** |

**共享模板：** 升级前由系统种入、且 `owner_id` 为空的数据，部门负责人及以上可见平台种子数字员工；普通操作员仅见自己的。

## 8. 组织权限与分层赋权

> 完整设计见 **[组织权限与赋权说明](./组织权限与赋权说明.md)**。

### 8.1 三类管理者

| 角色 | 入口 | 职责 |
|------|------|------|
| **平台 Admin** | 设置 → 组织与权限 | 建部门树、指定各部门**接口人**、指定**高管秘书**、维护人员层级 |
| **部门接口人** | 设置 → **本部门权限** | 在本部门子树内赋 `operator` / `dept_leader` / `auditor` |
| **高管秘书** | 设置 → **高管权限** | 给总监级及以上赋 `executive`（全公司大屏） |

### 8.2 Admin 初始化步骤

1. 登录 `admin` → **设置 → 组织与权限**
2. 创建部门（财务中心、制造中心等）；「高管办公室」类型选 **高管办公室**
3. 在部门列表下拉框为每个部门选择 **权限接口人**
4. 在「用户与角色」Tab：给总监设 **人员层级 = 总监级**；给秘书勾选 **高管秘书** 角色
5. 接口人 / 秘书 **重新登录** 后侧边栏出现对应赋权菜单

### 8.3 接口人与秘书的限制

- 接口人**不能**开通高管权限、不能修改组织树
- 秘书**不能**管理普通员工权限
- 任何人都**不能**给自己升权（接口人/秘书 lane）

### 8.4 赋权审计

Admin 可通过 API `GET /organization/audit-logs` 查看谁给谁改了什么角色。

## 9. 数据存储与自动清理

### 9.1 数据存在哪里？

| 数据类型 | 默认位置 | 说明 |
|----------|----------|------|
| 业务数据（用户、对话、配置等） | SQLite `backend/aiagnet.db` 或 **PostgreSQL** | 配置 `DB_HOST` 时使用远程 PG |
| 向量索引 | 本地 Chroma `backend/chroma_data` 或 **Milvus** | `VECTOR_STORE_TYPE=chroma\|milvus` |
| 上传文件 | `backend/uploads/` 或 MinIO | 配置 `MINIO_ENDPOINT` 时使用对象存储 |

查看当前数据库类型：访问 `/health`，响应中含 `database.backend`。

### 9.2 对话保留策略

- 默认保留 **30 天**（`CONVERSATION_RETENTION_DAYS`）
- 清理在后台调度器与打开会话列表时执行
- 删除会话会同时删除其消息记录

### 9.3 备份建议

- **PostgreSQL：** 定期 `pg_dump` 或使用云备份
- **Chroma / uploads：** 随业务数据一并备份目录
- **Milvus：** 按 Milvus 集群备份方案执行

## 10. 桌面自动化

路径：**桌面自动化** → http://localhost:3000/desktop-automation

### 9.1 适用场景

在 Windows 办公机上 **录制 GUI 操作** 并 **回放**，或通过 Chat / 智能体远程触发 Sidecar 执行演示。

### 9.2 启动 Sidecar（本机 Windows）

平台后端可在 Docker 或服务器上运行，但 **Sidecar 必须在用户 Windows 桌面** 运行：

**方式 A：双击 exe（推荐）**

```
release\desktop-sidecar\AIAGNET-Desktop-Sidecar.exe
```

同目录 `sidecar.env` 配置后端地址与登录账号（示例见 [桌面自动化与 Harness 说明](./桌面自动化与Harness说明.md)）。

**方式 B：Python 脚本**

```powershell
cd backend
$env:AIAGNET_BASE_URL="http://127.0.0.1:8000"
$env:AIAGNET_LOGIN="admin"
$env:AIAGNET_PASSWORD="admin123"
.\.venv\Scripts\python.exe ..\scripts\desktop_sidecar.py
```

### 9.3 Web 页操作

1. 确认页头 **Sidecar 在线**
2. **录制**：开始 → 操作 GUI → 填演示名 → 停止并保存
3. **回放**：演示列表点播放（页面点击视为已确认）
4. **待确认回放**：来自 Chat/智能体的任务在列表或 Chat 横幅中批准

### 9.4 对话中使用

1. Chat 绑定 **桌面操作员** 智能体
2. 发送如「列出桌面演示」「回放 xxx」
3. 若需确认，在 Chat **待确认的桌面回放** 横幅点 **批准执行**

### 9.5 相关配置

`backend/.env`：

```env
DESKTOP_REQUIRE_CONFIRMATION=true
DESKTOP_OPENADAPT_DATA_DIR=./desktop_openadapt_data
```

详细说明见 [桌面自动化与 Harness 说明](./桌面自动化与Harness说明.md)。

## 11. Agent Harness（工具确认门控）

Harness 在 Agent 调用工具前执行 **风险分级** 与 **人工确认**，避免 LLM 直接发起 HTTP、读邮件等外部操作。

### 10.1 工具风险级别

| 级别 | 代表工具 | 行为 |
|------|----------|------|
| L0 | calculator, web_search, get_datetime | 直接执行 |
| L1 | create_presentation | 执行 + 审计 |
| L2 | http_request, fetch_mail | **Chat 中需用户批准** |
| 自管 | desktop_replay, desktop_capture | 走桌面模块自有确认 |

### 10.2 Chat 中批准

绑定含 L2 工具的智能体后，输入区上方可能出现 **待确认的工具调用**（紫色横幅），点击 **批准执行** 或 **拒绝**。

### 10.3 不同入口策略

| 入口 | 说明 |
|------|------|
| Chat / 手动运行智能体 | L2 默认需确认 |
| 数字员工定时任务 | 自动放行（`auto_confirm`） |
| 桌面页直接播放 | 跳过桌面门控 |

### 10.4 配置

```env
HARNESS_REQUIRE_TOOL_CONFIRMATION=true
HARNESS_LLM_TIMEOUT_SEC=120
HARNESS_MAX_ITERATIONS_CAP=25
```

## 12. 运维与部署要点

### 11.1 必改环境变量（生产）

在 `backend/.env` 中：

```env
SECRET_KEY=请替换为至少32字符的随机字符串
DEFAULT_ADMIN_PASSWORD=强密码
ACCESS_TOKEN_EXPIRE_MINUTES=10080
CONVERSATION_RETENTION_DAYS=30
```

### 11.2 使用 PostgreSQL

```env
DB_HOST=192.168.x.x
DB_PORT=5432
DB_USER=aiagnet
DB_PASSWORD=your_password
DB_NAME=aiagnet
DB_SSL=prefer
```

修改后 **重启后端**；SQLite 本地文件不再作为主库。

### 11.3 依赖安装

新增认证依赖，升级后需：

```bash
cd backend
pip install -r requirements.txt   # 含 PyJWT
```

### 11.4 后端重启

修改 `.env`、数据库结构或认证逻辑后，必须重启 uvicorn：

```powershell
# 若端口被占用，先结束旧进程再启动
.\start_backend.ps1
```

### 11.5 Docker Compose

```bash
docker compose up -d
```

详见 README [Docker 章节](../README.md#docker)。Ollama 通常需在宿主机单独运行。

## 13. 常见问题

### Q1：登录后接口返回 401

- Token 可能过期，重新登录
- 确认 `SECRET_KEY` 未在中途修改（修改会使旧 Token 全部失效）
- 检查前端 `NEXT_PUBLIC_API_URL` 是否指向正确后端

### Q2：对话无回复 / 模型报错

1. 检查 **Model Hub** 默认模型是否可用
2. 在 **设置** 中确认个人 API Key 或全局 `.env` Key 有效
3. Ollama 用户：确认 `ollama list` 中有对应模型且服务在运行
4. 查看后端日志中的具体错误

### Q3：推荐问题一直加载

- 通常是 LLM 调用失败或超时；检查模型配置与 Key
- 附件过大可能导致分析变慢，可换较小文件试

### Q4：看不到别人创建的智能体

- 这是预期行为：用户数据已隔离，仅共享模板（无 owner）全员可见

### Q5：修改 Model Hub 推理参数不生效

- 保存后需确认 PATCH 成功；若仍异常，**重启后端** 后再试
- 部分参数仅特定 Provider 支持（如 `num_ctx` 仅 Ollama）

### Q6：数据在 SQLite 还是 PostgreSQL？

- 访问 http://localhost:8000/health
- 若配置了 `DB_HOST` 或 `DATABASE_URL=postgresql+...`，数据在 PostgreSQL
- 本地 `aiagnet.db` 可能为旧数据或开发残留

### Q7：Sidecar 一直显示离线？

- 确认本机已启动 `AIAGNET-Desktop-Sidecar.exe` 或 `desktop_sidecar.py`
- 检查 `sidecar.env` 中 `AIAGNET_BASE_URL`、账号密码是否与后端一致
- Sidecar 不能跑在 Docker 容器内，必须在 Windows 用户桌面

### Q8：Chat 里工具或回放不执行？

- 查看输入区上方是否有 **待确认** 横幅（桌面回放 / 工具调用），需点 **批准执行**
- 开发环境可临时设 `HARNESS_REQUIRE_TOOL_CONFIRMATION=false`（生产不推荐）

### Q9：前端页面空白或 500？

- 删除 `frontend\.next` 后重新 `npm run dev` 或 `next start`
- 强制刷新或访问 `/login`
