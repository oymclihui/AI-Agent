## 1. 快速上手

### 1.1 启动服务

**Windows（推荐）**

```powershell
# 项目根目录
.\start.ps1          # 同时启动前后端
# 或分别启动
.\start_backend.ps1
.\start_frontend.ps1
```

**手动启动**

```bash
# 后端（端口 8000）
cd backend
.venv\Scripts\activate    # Windows
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 前端（端口 3000）
cd frontend
npm run dev
```

浏览器访问：**http://localhost:3000**

- API 文档：http://localhost:8000/docs
- 健康检查：http://localhost:8000/health

### 1.2 首次登录

1. 打开 http://localhost:3000 ，自动跳转至 **登录页** `/login`
2. 使用默认管理员账号（首次启动自动创建）：
   - **工号：** `admin`
   - **密码：** `admin123`
3. 登录成功后进入首页；侧边栏可进入各功能模块

> **安全提示：** 生产环境请在 `backend/.env` 中修改 `DEFAULT_ADMIN_PASSWORD` 和 `SECRET_KEY`，并尽快修改管理员密码。

## 2. 登录与账号

### 2.1 登录方式

- 支持 **工号** 或 **邮箱** + 密码登录
- 登录状态保存在浏览器本地（JWT Token），默认有效期 **7 天**（由 `ACCESS_TOKEN_EXPIRE_MINUTES` 控制）
- 未登录时访问业务页面会自动跳转到 `/login`

### 2.2 注册新用户（可选）

若后端开放注册接口，可通过 API 注册：

```http
POST /api/v1/auth/register
Content-Type: application/json

{
  "employee_no": "10001",
  "email": "user@company.com",
  "password": "your-password",
  "display_name": "张三"
}
```

注册成功后返回 Token，与登录相同。

### 2.3 退出登录

进入 **设置** 页（侧边栏 **Settings / 设置**）→ 点击 **退出登录**。

## 3. 个人设置与 API Key

路径：**设置** → http://localhost:3000/settings

### 3.1 为什么需要个人 Key？

平台支持两种 LLM 密钥来源：

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 高 | **个人模型 Key**（设置页配置） | 仅当前用户使用，互不影响 |
| 低 | 全局 `.env`（如 `OPENAI_API_KEY`） | 所有用户共用，适合 Ollama 或统一网关 |

### 3.2 配置步骤

1. 打开 **设置** 页
2. 在「个人模型 Key」区域填写：
   - **Provider**：如 `openai`、`anthropic`
   - **Model ID**（可选）：限定该 Key 仅用于某模型
   - **API Key**：密钥本身
   - **Base URL**（可选）：OpenAI 兼容接口地址，用于内部网关
3. 点击 **保存**
4. 已保存的 Key 会显示脱敏预览（如 `sk-****abcd`），可单独删除

### 3.3 对接内部 OpenAI 兼容服务

示例（内部推理网关）：

| 字段 | 示例值 |
|------|--------|
| Provider | `openai` |
| Base URL | `https://your-internal-gateway/v1` |
| API Key | 网关分配的 Key |
| Model ID | 留空或填具体模型名 |

之后在 **Model Hub** 中创建 provider 为 `openai` 的模型配置，并填写相同 Base URL。

## 4. Model Hub（模型中心）

路径：**Model Hub** → http://localhost:3000/models

### 4.1 功能概览

- **查看** 已配置的 LLM 列表
- **新建** 模型配置（名称、Provider、模型 ID、Base URL 等）
- **编辑** 已有配置
- **设为默认**：对话与 Agent 未指定模型时使用
- **删除** 不再使用的配置
- **推理参数**：temperature、top_p、max_tokens、stop 等

### 4.2 新建模型配置

1. 点击 **新建** / **Add**
2. 填写基本信息：
   - **名称**：显示用，如「GPT-4o 生产」
   - **Provider**：`openai` / `anthropic` / `ollama` / `azure` 等
   - **Model ID**：如 `gpt-4o`、`qwen3.6:35b`
   - **Base URL**（OpenAI 兼容或 Ollama 时）：如 `http://localhost:11434`
3. 展开 **推理参数**（可选）：
   - `temperature`：0–2，越高越随机
   - `top_p`：核采样
   - `max_tokens`：最大输出长度
   - 其他参数见表单说明
4. 保存

### 4.3 设为默认模型

在模型列表中点击 **设为默认**；系统全局默认对话将使用该配置（用户未在 Chat 中单独选模型时）。

### 4.4 Ollama 本地模型

| 字段 | 值 |
|------|-----|
| Provider | `ollama` |
| Model ID | 本机已 pull 的模型名，如 `qwen3.6:35b` |
| Base URL | `http://localhost:11434`（或 `.env` 中 `OLLAMA_BASE_URL`） |

确保本机 Ollama 已启动且模型已下载：

```bash
ollama pull qwen3.6:35b
ollama pull nomic-embed-text   # 知识库嵌入
```

## 5. 对话（Chat）

路径：**Chat** → http://localhost:3000/chat

### 5.1 基本对话

1. 左侧 **新建对话** 或选择历史会话
2. （可选）选择绑定的 **Agent**，自动注入其技能与工具
3. （可选）选择 **模型**
4. 输入消息，Enter 发送；支持 **流式输出**

### 5.2 附件与推荐问题

1. 点击输入框旁的 **附件** 按钮，上传文档（如 PDF、Word、TXT 等）
2. 上传成功后，系统会用 LLM 分析附件内容，生成 **3 条推荐问题**
3. **点击推荐问题** → 自动填入输入框，可编辑后发送
4. 也可忽略推荐，自行输入问题

> 推荐问题基于当前附件生成；更换附件会重新分析。

### 5.3 删除会话

| 操作 | 方法 |
|------|------|
| 删除单条 | 会话列表项右侧 **垃圾桶** 图标 |
| 清空全部 | 会话列表顶部 **清空全部** 按钮 |

删除后不可恢复，请确认后再操作。

### 5.4 会话自动过期

- 超过 **30 天** 未更新的会话会被系统自动清理
- 可在 `backend/.env` 调整：`CONVERSATION_RETENTION_DAYS=30`
- 打开会话列表时也会触发过期清理

## 6. 会话沉淀：存为技能 / 知识库

在 **当前对话** 打开时，工具栏提供：

### 6.1 存为技能

1. 点击 **存为技能**
2. 系统将对话记录交给 LLM，提炼为 **SOP 格式 Markdown**（适用场景、操作步骤、输出格式、注意事项）
3. 生成后可在 **Skills** 页查看、编辑，并绑定到 Agent

适用：重复性工作流程、操作规范、方法论沉淀。

### 6.2 存入知识库

1. 点击 **存入知识库**
2. 系统将对话整理为 Markdown 文档，写入您的知识库并完成向量索引
3. 之后在 **Knowledge** 页可检索该内容

适用：会议纪要、调研结论、FAQ 等事实性内容。

## 7. 数据隔离与共享模板

登录后，您创建或导入的资源会标记 **所有者（owner_id）**：

| 模块 | 隔离规则 |
|------|----------|
| 智能体 Agents | 仅见/改自己的；平台种子模板全员可见 |
| 技能 Skills | 同上 |
| 工作流 Workflows | 同上 |
| 知识库 Knowledge | 同上 |
| 对话 Chat | 仅自己的会话 |
| 数字员工 Employees | 同上 |

**共享模板：** 升级前由系统种入、且 `owner_id` 为空的数据，所有用户可见，但普通用户不能编辑，仅作参考模板。

## 8. 数据存储与自动清理

### 8.1 数据存在哪里？

| 数据类型 | 默认位置 | 说明 |
|----------|----------|------|
| 业务数据（用户、对话、配置等） | SQLite `backend/aiagnet.db` 或 **PostgreSQL** | 配置 `DB_HOST` 时使用远程 PG |
| 向量索引 | 本地 Chroma `backend/chroma_data` 或 **Milvus** | `VECTOR_STORE_TYPE=chroma\|milvus` |
| 上传文件 | `backend/uploads/` 或 MinIO | 配置 `MINIO_ENDPOINT` 时使用对象存储 |

查看当前数据库类型：访问 `/health`，响应中含 `database.backend`。

### 8.2 对话保留策略

- 默认保留 **30 天**（`CONVERSATION_RETENTION_DAYS`）
- 清理在后台调度器与打开会话列表时执行
- 删除会话会同时删除其消息记录

### 8.3 备份建议

- **PostgreSQL：** 定期 `pg_dump` 或使用云备份
- **Chroma / uploads：** 随业务数据一并备份目录
- **Milvus：** 按 Milvus 集群备份方案执行

## 9. 运维与部署要点

### 9.1 必改环境变量（生产）

在 `backend/.env` 中：

```env
SECRET_KEY=请替换为至少32字符的随机字符串
DEFAULT_ADMIN_PASSWORD=强密码
ACCESS_TOKEN_EXPIRE_MINUTES=10080
CONVERSATION_RETENTION_DAYS=30
```

### 9.2 使用 PostgreSQL

```env
DB_HOST=192.168.x.x
DB_PORT=5432
DB_USER=aiagnet
DB_PASSWORD=your_password
DB_NAME=aiagnet
DB_SSL=prefer
```

修改后 **重启后端**；SQLite 本地文件不再作为主库。

### 9.3 依赖安装

新增认证依赖，升级后需：

```bash
cd backend
pip install -r requirements.txt   # 含 PyJWT
```

### 9.4 后端重启

修改 `.env`、数据库结构或认证逻辑后，必须重启 uvicorn：

```powershell
# 若端口被占用，先结束旧进程再启动
.\start_backend.ps1
```

### 9.5 Docker Compose

```bash
docker compose up -d
```

详见 README [Docker 章节](../README.md#docker)。Ollama 通常需在宿主机单独运行。

## 10. 常见问题

### Q1：登录后接口返回 401

- Token 可能过期，重新登录
- 确认 `SECRET_KEY` 未在中途修改（修改会使旧 Token 全部失效）
- 检查前端 `NEXT_PUBLIC_API_URL` 是否指向正确后端

### Q2：对话无回复 / 模型报错

1. 检查 **Model Hub** 默认模型是否可用
2. 在 **设置** 中确认个人 API Key 或全局 `.env` Key 有效
3. Ollama 用户：确认 `ollama list` 中有对应模型且服务在运行
4. 查看后端日志中的具体错误

### Q3：推荐问题一直加载

- 通常是 LLM 调用失败或超时；检查模型配置与 Key
- 附件过大可能导致分析变慢，可换较小文件试

### Q4：看不到别人创建的智能体

- 这是预期行为：用户数据已隔离，仅共享模板（无 owner）全员可见

### Q5：修改 Model Hub 推理参数不生效

- 保存后需确认 PATCH 成功；若仍异常，**重启后端** 后再试
- 部分参数仅特定 Provider 支持（如 `num_ctx` 仅 Ollama）

### Q6：数据在 SQLite 还是 PostgreSQL？

- 访问 http://localhost:8000/health
- 若配置了 `DB_HOST` 或 `DATABASE_URL=postgresql+...`，数据在 PostgreSQL
- 本地 `aiagnet.db` 可能为旧数据或开发残留

## 附录：主要 API 速查

前缀：`/api/v1`（需 Header：`Authorization: Bearer <token>`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/login` | 登录 |
| POST | `/auth/register` | 注册 |
| GET | `/auth/me` | 当前用户 |
| POST/GET/DELETE | `/auth/me/model-keys` | 个人模型 Key |
| GET/POST/PATCH/DELETE | `/models/configs` | 模型配置 CRUD |
| POST | `/models/configs/{id}/set-default` | 设默认模型 |
| POST | `/chat/suggest-questions` | 附件推荐问题 |
| DELETE | `/chat/conversations/{id}` | 删除会话 |
| DELETE | `/chat/conversations` | 清空全部会话 |
| POST | `/chat/conversations/{id}/save-as-skill` | 存为技能 |
| POST | `/chat/conversations/{id}/save-to-knowledge` | 存入知识库 |

完整接口：http://localhost:8000/docs
