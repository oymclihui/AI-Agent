# 单位电脑部署与首次登录指南

适用于：**Windows 交付包（zip）** 或 **双击 `AI-AGENT.bat` 启动**。  
目标：在单位电脑上配置数据库后即可登录使用，**不必一开始就连 VastBase**。

---

## 一、整体流程

```mermaid
flowchart LR
    A[解压 zip] --> B[双击 AI-AGENT.bat]
    B --> C{首次运行?}
    C -->|是| D[install.ps1 自动安装依赖]
    C -->|否| E[启动前后端]
    D --> E
    E --> F[浏览器打开 localhost:3000]
    F --> G{数据库已初始化?}
    G -->|否| H[/setup 首次部署向导]
    H --> I[填写 PG 或 VastBase 连接]
    I --> J[测试连接 + 一键建表]
    J --> K[重启应用]
    K --> L[登录 admin / admin123]
    G -->|是| L
    L --> M[进入对话 / 各模块]
```

---

## 二、环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10/11 |
| Python | 3.10+（安装时勾选 **Add to PATH**） |
| Node.js | 18+ LTS |
| 数据库 | **PostgreSQL 或 VastBase**（二选一，协议兼容） |

> **重要：** 系统不支持 SQLite。必须有一台可访问的 PostgreSQL 兼容数据库。

---

## 三、没有 VastBase 怎么办？

**可以先用 PostgreSQL 完成全流程验证：**

| 场景 | 建议 |
|------|------|
| 家里测试 | 本机 Docker PostgreSQL，或已有测试库 |
| 单位暂无上云 | 先用单位提供的 **PostgreSQL 测试实例** |
| 正式环境 | 上线后在 **设置 → 数据库** 改为 VastBase 连接 |

VastBase 与 PostgreSQL 使用相同的连接参数（主机、端口、用户名、密码、库名、schema），切换时只需改 `DB_DRIVER=vastbase` 和对应地址。

## 四、操作步骤

### 角色分工（重要）

| 角色 | 能做什么 | 不能做什么 |
|------|----------|------------|
| **平台管理员（你）** | 持有 `SETUP_TOKEN.admin.txt`，完成 `/setup` 首次建库；登录 `admin` 后在「设置→组织」创建其他用户 | — |
| **普通用户** | 使用管理员分配的工号/邮箱登录 | **无法**配置数据库、**无法**执行首次部署（无安装令牌） |

安装包可以发给多人，但 **`SETUP_TOKEN.admin.txt` 只给你自己**，不要放进 zip 或发给同事。

### 1. 打包（开发机）

```powershell
cd E:\AIAGNET
.\scripts\package_win_release.ps1
```

得到 `release\aiagnet-win-YYYYMMDD.zip`，拷贝到单位电脑解压。

### 2. 启动（单位电脑）

双击 **`AI-AGENT.bat`**（可将此 bat 用 Bat To Exe 等工具转为 exe）。

首次会自动执行 `install.ps1`（创建 venv、安装依赖）。

### 3. 首次部署向导（仅管理员）

浏览器打开后，管理员进入：

**http://localhost:3000/setup**

1. 输入 **安装令牌**（`SETUP_TOKEN.admin.txt` 中的内容）
2. 选择 **PostgreSQL**（测试）或 **VastBase**（正式）
3. 填写连接信息 → **测试连接** → **测试连接并初始化**
4. **关闭窗口，再次双击 AI-AGENT.bat** 重启
5. 用 `admin` / `admin123` 登录
6. 在 **设置 → 组织与权限** 为同事创建账号

普通用户打开系统只会看到登录页提示「系统尚未初始化，请联系管理员」，**没有令牌无法进入配置页**。

### 4. 普通用户登录

| 字段 | 默认值 |
|------|--------|
| 账号 | `admin` |
| 密码 | `admin123` |

可在 `backend\.env` 中修改 `DEFAULT_ADMIN_PASSWORD`（需在首次建表前改，或登录后在组织设置里改密码）。

登录后默认进入 **对话** 页。

---

## 五、以后切换 VastBase

1. 登录管理员账号  
2. **设置 → 数据库**  
3. 类型选 **VastBase 海量**，填写单位提供的连接信息  
4. 测试连接 → 保存 → **在新 schema 下一键建表**（若 public 已有表，请用 `aiagnet` 等新 schema）  
5. 重启后端

## 六、常见问题

**Q：双击 bat 后浏览器 404？**  
确认只运行一个实例，访问 http://localhost:3000 ，强制刷新 Ctrl+Shift+R。

**Q：浏览器打开一片空白？**  
1. 确认解压的是 **完整 release zip**（含 `runtime\`、`frontend\.next\`、`frontend\node_modules\`），不要只拷源码文件夹。  
2. 双击 `AI-AGENT.bat` 后**不要关**弹出的两个 PowerShell 窗口（后端/前端）。  
3. 直接访问 http://localhost:3000/login （不要只开首页 `/`）。  
4. 运行同目录下的 **`diagnose_local.ps1`** 查看端口与 `/health` 是否正常。  
5. 查看 **`ai-agent-start.log`**；若杀毒软件拦截 `runtime\node\node.exe`，请加白名单。  
6. 解压路径建议 **`D:\AIAGNET`** 等短英文路径，避免过深或含特殊字符的路径。

**Q：登录提示无法连接服务器？**  
后端未启动或 8000 端口被占用，重新运行 `AI-AGENT.bat`。

**Q：初始化提示 schema 已有表？**  
说明该 schema 里已有 AI-AGENT 业务表。换一个 schema 名（如 `aiagnet_dev`）再初始化，**不会删除或覆盖原表**。

**Q：LLM 对话无响应？**  
数据库与登录无关。需在 **设置 → 模型** 或 `backend\.env` 配置 Ollama / 内网模型地址。

**Q：如何改成 exe？**  
将 `AI-AGENT.bat` 用 Bat To Exe Converter 等工具打包；exe 需与整个解压目录放在同一文件夹。

## 七、迁移到新单位服务器（改 IP）

**运行时只读 `backend/.env`（或 设置 → 数据库），代码里不再写死旧 IP。**

迁移 checklist：

1. 修改 `backend/.env`：
   - `DB_HOST` / `DATABASE_URL` → 新库地址
   - `OLLAMA_BASE_URL` → 新 Ollama 地址
   - `MILVUS_URI` → 新 Milvus（若使用）
   - `APP_PUBLIC_URL` / `ALLOWED_ORIGINS` → 新访问域名或 IP
2. **重启后端**（Ollama 模型地址会在启动时从 `.env` 同步到数据库）
3. Docker 部署：复制 `.env.docker.example` 为 `.env`，把 `YOUR_SERVER_HOST` / `YOUR_DB_HOST` 改成实际值
4. 远程脚本：先设置环境变量再执行：
   ```powershell
   $env:DEPLOY_HOST = "新服务器IP"
   $env:DEPLOY_DB_HOST = "新数据库IP"   # 可与 DEPLOY_HOST 相同
   $env:PUBLIC_HOST = "公网IP或域名"     # 可选
   ```
5. VastBase 迁移：复制 `backend/.env.vastbase.example`，填写 `SOURCE_DB_*` 与 `TARGET_DB_*`，再运行 `migrate_to_vastbase.py`
